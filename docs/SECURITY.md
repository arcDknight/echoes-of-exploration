# Security guide
## Security and Privacy

The Echoes of Exploration project follows security-conscious development practices to help protect the application and its users.

### Security Practices

- **Credential Protection:** Private credentials and API keys should not be included in publicly accessible source code.
- **Environment Configuration:** Sensitive configuration values are managed separately from application source files.
- **Secure Communication:** HTTPS is used where supported by the deployment environment.
- **Input Validation:** Application inputs are handled with validation to reduce misuse and unexpected behaviour.
- **Output Handling:** Application responses are processed carefully to reduce the risk of unsafe content being displayed.
- **Dependency Maintenance:** Project dependencies are reviewed and maintained to help address known security issues.
- **Error Handling:** Errors are handled carefully to avoid unnecessarily exposing internal application information.
- **Access Control:** Application components are designed to limit unnecessary exposure of internal resources.

### Privacy

The project is designed to operate without requiring user accounts or a user registration system.

Users should avoid entering passwords, personal information, confidential information or other sensitive data into the application.

### Security Limitations

No application can guarantee complete protection against every security threat. AI-generated responses may occasionally be inaccurate or unexpected.

The project has not undergone an independent security audit. Security practices and deployment configurations should not be interpreted as a guarantee that the application is free from vulnerabilities.

### Responsible Use

Users are encouraged to use the application responsibly and report any suspected security issues to the project team.
